# GloGraph — Node & Edge Specification

## Node Data Model

```typescript
interface GloNode {
  id: string;                      // UUID v4, generated by Rust
  title: string;                   // optional (may be empty); UI shows a derived label — see lib/nodeDisplay
  description?: string | null;     // free-form text
  eventDate?: string | null;       // ISO date "YYYY-MM-DD"
  dateAdded: string;               // ISO datetime, set at creation, never changed
  x: number;                       // canvas position (flow coordinates)
  y: number;
  color?: string | null;           // hex override; null = use the colour-driving param
  confidence?: number | null;      // 0–100
  impactMagnitude?: number | null; // 1–10
  externalId?: string | null;      // stable script-controlled id (HTTP API / SDK only)
  tags: string[];                  // free-form tags, filterable
  links: NodeLink[];               // external URLs
  media: NodeMedia[];              // attached images, video, or audio
  paramValues: NodeParamValue[];   // per-node values for the active preset's params
  kind?: NodeKind;                 // 'standard' | 'note' | 'image' | 'video' | 'audio' | 'file'
  width?: number | null;           // canvas size for resizable items (null = default)
  height?: number | null;
  renderMarkdown?: boolean;        // notes only: render body as markdown (default true) vs raw text
  showThumbnail?: boolean;         // file nodes only: show thumbnail/first-page preview (default true) vs icon
}

// Node variant discriminator (see specs/GRAPH_ITEMS_DESIGN.md). 'standard' is a
// normal typed node; the others are the lightweight "graph items". Stored in
// nodes.kind (TEXT NOT NULL DEFAULT 'standard'); legacy data reads back as
// 'standard'. As of file format v6 it round-trips through export/import.
type NodeKind = 'standard' | 'note' | 'image' | 'video' | 'audio' | 'file';

// NOTE: `category`, `subCategory`, and `status` are no longer node fields. They
// are ordinary preset params (select_color) stored in `paramValues` — see the
// Settings System below. The backend also carries an API-only `data_source`
// JSON blob, managed via the HTTP API, never the desktop UI.

interface NodeLink {
  id: string;
  nodeId: string;
  url: string;
  label?: string | null;  // display text; falls back to raw URL
}

interface NodeMedia {
  id: string;
  nodeId: string;
  label: string;          // display name (may be empty)
  src: string;            // absolute file path or URL
  srcType: 'file' | 'url';
  mediaType: 'image' | 'video' | 'audio';
  sortOrder: number;
  showOnCard: boolean;    // render inline on the node card
}

interface NodeParamValue {
  id: string;
  nodeId: string;
  paramDefId: string;     // references NodeParamDef.id
  value?: string | null;
  isEnabled: boolean;
  showOnCard: boolean;    // render this param on the node card
}
```

### Field Rules

| Field            | Required | Notes                                                             |
|------------------|----------|-------------------------------------------------------------------|
| `title`          | No       | Short, specific — "Fed Rate Hike +75bps Jun 2022" not "Rate hike". **Optional since the graph-items work** (Phase 28): an empty title falls back to a derived label (media label → first description line → "Untitled <kind>") via `nodeDisplayLabel`. Stored as `''` (column stays `NOT NULL`). |
| `eventDate`      | No       | When the event happened in the real world                         |
| `dateAdded`      | Auto     | Set by Rust at creation. Never editable.                          |
| `confidence`     | No       | 0–100 certainty. **Legacy macro field** — no longer editable in the desktop node panel; preserved on edit and still settable via the HTTP API. Shown read-only on the card if present. |
| `impactMagnitude`| No       | 1–10 significance. **Legacy macro field** — same as `confidence`: not panel-editable, preserved, API-settable. |
| `description`    | No       | Context and market impact. 1–4 sentences ideal.                   |
| `color`          | No       | Hex override. If set, takes priority over the colour-driving param.|
| `tags`           | No       | Free-form string tags; filterable in the sidebar and HTTP API.    |
| `externalId`     | No       | Stable id set by scripts via the HTTP API/SDK. Not editable in the desktop UI. |
| `links`          | No       | Source articles, charts, FRED pages, etc.                         |
| `media`          | No       | Images, video, or audio. Stored in `node_media` (incl. `showOnCard`). EditOnly — appears in NodePanel via "Add field" in edit mode only. |
| `paramValues`    | No       | Per-node values for the active preset's params (incl. the category/status/domain selects). On a **new** node the panel shows the active preset's params up front (so the form reflects the current preset); on an existing node, params with values show and others are added via "Add field." |

## Settings System (Presets)

> **Model note:** "Category", "Status", "Domain", etc. are no longer dedicated node columns —
> they are ordinary **preset params** of type `select_color`/`select` whose values live in
> `node_param_values`. Exactly one param per preset carries the `drivesColor` flag and acts as the
> node's colour/badge driver (the old "category"). The prose below is kept for conceptual background.

Params (and their options) are **not hardcoded**. They live in the database under named **Presets**.
One preset is active at a time; the active preset determines what params appear in node forms and
what the sidebar can filter on.

### Key rules

- The `category`, `subCategory`, and `status` fields on a node store the `value_slug` string —
  a stable identifier that does not change when the label is renamed.
- If a category slug on a node no longer exists in the active preset, the node displays with a
  fallback colour and shows the raw slug. No data is lost.
- Switching presets does not migrate or transform node data. Slugs that exist in both presets
  continue to resolve; slugs that don't become unresolved.

### Built-in presets

GloGraph seeds four built-in presets (Macro Economics, System Behavior, Knowledge Map, Project
Tracker). Their exact fields and options are **seeded in `../../GloGraphDesktopApplication/src-tauri/src/db.rs`** and summarized in
[UX_SPEC.md](../design/UX_SPEC.md) §15 — that is the source of truth, so option lists aren't duplicated here
(they drift). For example, after the Phase 15 rework the Macro preset's colour-driving param is
**Domain** (Political / Economic / Financial / Policy / …) plus a **Region** param — not the original
"Category" set.

### Custom Node Parameters

Defined in Graph Settings → Parameters. Each definition has:

| Field | Notes |
|-------|-------|
| `displayName` | Label shown in NodePanel |
| `paramType` | `text`, `number`, `boolean`, `select`, `select_color` |
| `defaultValue` | Pre-filled value (optional) |
| options | For `select`/`select_color`: rows in `node_param_options` (slug + label + colour), not a comma-separated string |

Custom parameters follow the same **add-field pattern** as other optional node fields. The
"Custom Parameters" section only appears in the node panel after the user explicitly adds it
via the `+ ADD FIELD` dropdown. Param values are saved per-node; omitting the section leaves
existing values untouched (the section must be visible for values to be written on save).

---

## Categories = a preset's `select_color` options

A node's "category" is just the selected option of the preset's colour-driving (`drivesColor`)
`select_color` param — each option is a `(value_slug, label, colour)` row in `node_param_options`.
User presets define their own; the built-in presets' options are seeded in `../../GloGraphDesktopApplication/src-tauri/src/db.rs` and
summarized in [UX_SPEC.md](../design/UX_SPEC.md) §15. **Value slugs are stable** — renaming a label never touches
node data (a node stores the slug, not the label or a UUID; see *value_slug pattern* in HANDOFF). An
unresolved slug (option deleted, or preset switched) renders with a fallback colour; no data is lost.

## Node Visual Design (NodeCard)

Cards use a **compact-by-default** layout. Only the title is visible at rest; all other content
expands on hover (300ms delay), selection, or when the expand pin is active.

**Compact state (default, ~28px tall):**
```
┌─ ███ ──────────────────────────────────────── ─┐
│  ▌  Fed Rate Hike +75bps              [📌]     │  ← title row; pin icon appears on hover
└────────────────────────────────────────────────┘
  ●                                          ●     ← handles appear on hover
```

**Expanded state (hover / selected / pinned-open):**
```
┌─ ████ ─────────────────────────────────────────┐  ← stripe widens to 5px
│  ▌  Fed Rate Hike +75bps              [📌]     │  ← title row
│  [ECONOMIC]                 2022-06-15         │  ← badge + event date
│  Federal Reserve raised interest rates by...  │  ← description preview (≤80 chars)
│  Param Name    value                           │  ← custom params (showOnCard=true)
│  ⇄ 3  ⌗ 2  🖼 1  🎵 1                  🔒    │  ← meta row
│  ─────────────────────────────────────────    │
│  [inline image]                               │  ← on-card media
│  [▶ ──────── 0:12/1:34]                      │  ← AudioPlayer
└────────────────────────────────────────────────┘
```

Meta row icons: `⇄` (edge count), `Link2` (links), `Image` (images), `Film` (video), `Music2`
(audio) — each shown only when > 0. `Lock` (cyan, captured by region). (The position-pin no longer
has a meta badge — its state is shown by the header toggle below.)

**Title-row toggles (right of the title):**
- **Position pin** (`.node-card__pin-toggle`): `Pin` when unpinned / `PinOff` when pinned — toggles
  whether the node can be dragged (`togglePin` → `pinnedNodeIds`, `nodes.is_pinned`). On every kind.
- **Keep-open** (`.node-card__expand-toggle`): a chevron toggle (`ChevronsUpDown` → `ChevronsDownUp`)
  that locks the card expanded (`togglePinnedExpand` → `pinnedExpandIds`, `nodes.is_expand_pinned`).
  Hidden on always-expanded item cards. (Its icon was `Pin` until Phase 34, which collided with the
  position-pin — now distinct.)

Both buttons are **always visible in the amber accent** (Phase 34 — the icon shape conveys on/off
state; they brighten on hover); both states are **persisted** (Phase 20) and survive restart,
tab-switch and export.

**On-card media (`.node-card__media`):** the container is `nodrag` only — wheel-zoom and click-drag-pan
work while hovering it (the `<video>` and audio elements keep their own scoped `nowheel nopan` for
their controls). Each image/video/audio slot shows a **Maximize** button on hover that opens a
fullscreen modal (`createPortal` to `document.body`: image / `<video controls>` / audio player; close
with ✕ or Escape).

### Card States

| State | Details visible | Visual change |
|-------|-----------------|---------------|
| Default (compact) | No | Title only, ~28px tall |
| Hover | Yes (300ms delay) | Handles fade in; details expand |
| Selected | Yes (instant) | Amber border + `box-shadow: 0 0 0 1px var(--accent)` |
| Connecting source | Yes (instant) | `.node-card--connecting`; stays expanded for full drag |
| Pinned open | Yes (instant) | `.node-card--pinned-open`; pin icon amber |
| Edge endpoint hover | No (glow only) | Amber outer glow `0 0 0 2px rgba(214,139,42,0.75)` — no expand |
| Dimmed (filter) | No | `opacity: 0.22`, slightly recovers on hover |

### Graph-item variants (`kind`)

When `kind` is not `standard`, the card renders content-first with the primary content **always
visible** (not hover-gated), while keeping the shared chrome (handles, stripe, title/caption row,
expand pin, fullscreen media modal):

- **`note`** — the description renders text-first (`.node-card__note-body`, capped at 220px); an
  empty note shows a muted "Untitled note". The body renders as **markdown** (a lean subset —
  headings, bold/italic/strike, inline + fenced code, lists, blockquote, hr, links) by default; a
  per-note title-row toggle (`renderMarkdown`, default on) switches between the styled view and a raw
  plain-text view. Markdown source still lives in `description`; see `lib/markdown.tsx`. **Edit** the
  body by double-clicking it or clicking the title-row **edit (pencil) button** (single click selects);
  commits on blur, undoable.
- **`image` / `video` / `audio`** — the single attached media renders media-first
  (`.node-card__item-media`, reusing the standard image/video/`AudioPlayer` slots + maximize modal).
- **`file`** — an attached file (local or URL; `node_media` with `mediaType: 'file'`); the title
  defaults to the filename (editable). `FilePreview.tsx` picks a preview tier by type: image →
  thumbnail; **PDF → first-page-only** thumbnail (rendered with pdf.js); text/markdown → first ~4 KB;
  Office (.docx/.pptx/.xlsx) → embedded thumbnail; anything else → a type icon + filename. A per-file
  title-row toggle (`showThumbnail`, default on) flips between the preview and an icon-only view; an
  "open" button hands the file to the OS. Local-file previews are desktop-only (a Live Share guest /
  the web demo degrades to the icon).

No category badge shows by default (items carry no params). See
[GRAPH_ITEMS_DESIGN.md](GRAPH_ITEMS_DESIGN.md). Connecting/locking/etc. are identical to a standard
node because items *are* nodes.

### Connection Handles

- 4 handles (top, right, bottom, left) — all typed as `source` with `ConnectionMode.Loose` so any
  handle accepts incoming connections
- Hidden by default (`opacity: 0.3`); fade to `0.65` on card hover; full amber on direct hover
- Drag from any handle to any other node to create an edge
- The 300ms card-expand hover delay is critical here: it prevents the card from growing (and thus
  shifting the handle position) during the brief moment the pointer passes through the card body
  on the way to grab a handle

## Edge Data Model

```typescript
interface GloEdge {
  id: string;                          // UUID v4
  sourceId: string;                    // node ID where the edge starts
  targetId: string;                    // node ID where the edge ends
  sourceHandle?: string | null;        // 'top' | 'right' | 'bottom' | 'left'
  targetHandle?: string | null;
  paramValues: EdgeParamValue[];       // per-edge values for the active preset's edge params
  waypoints?: WaypointPoint[] | null;  // custom routing control points
  label?: string | null;               // free-text quick label shown at the edge midpoint
  externalId?: string | null;          // stable script-controlled id (HTTP API / SDK only)
  color?: string | null;               // hex stroke override; null = use the drivesColor param
}

interface EdgeParamValue {
  id: string;
  edgeId: string;
  paramDefId: string;   // references EdgeParamDef.id
  value?: string | null;
  isEnabled: boolean;
}
```

> `edgeType` / `strength` / `directed` / `notes` no longer exist. Relationship, direction,
> strength, and line style are all driven by **edge params** (see below); the old free-text
> `notes` is now `label`.

## Edge Params & Visual Encoding

Edges have no fixed "type". Each preset defines **edge params**; four optional flags on an
`EdgeParamDef` map a param onto the edge's appearance:

| Flag          | Param type     | Drives                                                          |
|---------------|----------------|-----------------------------------------------------------------|
| `drivesArrow` | `boolean`      | Arrowhead visibility (true → directed)                          |
| `drivesStyle` | `select`       | Path style: `default` (bezier), `straight`, `step`, `smoothstep`|
| `drivesColor` | `select_color` | The relationship **label** shown at the edge midpoint (no longer the stroke colour — Phase 40) |
| `drivesWidth` | `number`       | Stroke width (≤3 → thin, ≤7 → medium, else thick)               |

The built-in **Macro Economics** preset seeds a `Causation` (colour) param with options like
*Caused By, Correlates With, Amplifies, Offsets, Hedges Against, Reacts To, Preceded By*, plus
`Directed` (arrow), `Line Style`, and `Strength`. Other presets (System Behavior, Knowledge Map,
Project Tracker) seed their own edge params.

**Stroke colour (Phase 40).** Edge stroke colour is the per-edge `color` field (a hex override, set
via the EdgePanel **Edge Color** swatch picker or `PATCH /api/edges/{id}` `color`). With none set an
edge defaults to **white** (`#ffffff`); the `drivesColor` param now only supplies the midpoint label,
not the stroke. **Selected** edges draw in amber (`#ffb000`). (Built-in demos bake an explicit `color`
on every edge so they stay colourful.)

A free-text **`label`** (separate from params and the colour) can be set per edge — double-click an
edge to edit it inline; over HTTP, `PATCH /api/edges/{id}` with a `label` field. It renders under the
param label at the midpoint.

**Routing mode** (`bezier` | `waypoints` | `orthogonal`) is a global app setting, not per-edge.
Custom `waypoints` reshape the edge; in **waypoints** mode the path is a **smooth Catmull-Rom spline**
through the points (Phase 40), in **orthogonal** mode it is right-angled. Clear waypoints from the
edge's right-click menu.

## Region Data Model

Regions are labelled rectangles that group nodes visually.

```typescript
interface GloRegion {
  id: string;
  title: string;
  x: number; y: number;
  width: number; height: number;
  color?: string | null;
  zOrder: number;     // manual front/back order; higher = front
  createdAt: string;
}
```

- A node is a **member** of a region when its **center point** is inside the region (`isNodeInRegion`
  in `../../GloGraphDesktopApplication/src/lib/regionMembership.ts`) — size-independent, so a small nested region can still capture a
  node. This single rule drives locking, "select members", auto-fit, and copy/duplicate. (A region
  is a member of another region when it is **smaller** than that region and ≥50% of its area overlaps
  it — `isRegionInRegion`; the smaller-than rule keeps containment one-directional so a child region
  can't capture its bigger parent.)
- Containment and other shared behaviors live on a small **graph-object class hierarchy**
  (`../../GloGraphDesktopApplication/src/lib/graphObject.ts`): abstract `GraphObject` (`id`/`kind`/`bounds`/`label`/`isSelectable`/
  `isDeletable`/`canLock`) with `NodeObject`/`EdgeObject`/`RegionObject`; `RegionObject.contains()`
  is the membership behavior every membership check routes through, so object types behave consistently.
- **Stacking:** larger-area regions render behind smaller ones (so nested regions stay clickable);
  the selected region wins exact-size ties. `zOrder` overrides this — **Bring to Front / Send to
  Back** (region right-click menu) set it; it persists and round-trips through export/import.
- A locked region drags its members with it; minimize collapses it to its header bar. Region move
  and resize are undoable.

## Best Practices for Building the Graph

### Titling nodes
- Include the key metric or qualifier: "Fed Hike +75bps" not just "Rate Hike"
- Include time if it disambiguates: "SVB Collapse (Mar 2023)"
- Keep under 60 characters so the card doesn't overflow

### Connecting events
- Prefer directed edges with explicit type over undirected/unclassified
- Set strength to reflect your confidence × magnitude (1 = weak/speculative, 10 = direct/confirmed)
- Add notes on the edge to capture your reasoning — this is the analytical layer

### Category discipline
- Use `market` for price action events (oil at $130, VIX spike)
- Use `economic` for macro data releases and policy decisions (CPI, rate hikes)
- Use `political` for decisions made by governments/actors (war, sanctions, elections)
- Use `energy` specifically for energy supply/infrastructure events (pipeline, OPEC)
- Reserve `natural` for non-human-origin events (earthquakes, pandemics, weather)

## Future: AI-Assisted Node Creation

When the scraper pipeline is added, nodes will be created with:
- `title` extracted by Claude from the article headline/summary
- `description` summarised to 2–3 sentences
- `category` classified by Claude
- `eventDate` parsed from article dateline
- `links` containing the source URL
- Edges inferred from co-occurrence + Claude reasoning, with `strength` derived from
  a causality score (0.0–1.0 mapped to 1–10)

The existing data model supports this without schema changes.
